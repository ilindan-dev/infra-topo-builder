# ADR 0001: Технологический стек проекта

## Статус

Принято (Accepted)

## Контекст

В рамках разработки микросервиса агрегации логов необходимо выбрать технологический стек, который
обеспечит высокую скорость разработки в условиях жесткого дедлайна, надежность обработки больших файлов и строгую
типизацию работы с БД. Сервис должен реализовывать REST API и сохранять топологию в PostgreSQL.

## Решение

Я принял следующий базовый технологический стек:

1. **Go версии 1.26**
    - *Обоснование:* Использование встроенного улучшенного роутера `net/http` (позволяет избежать сторонних фреймворков
      вроде `gin`/`chi`), а также новый функционал применимый к асинхронной обработке, работе с файловой системой и
      просто
      типами данных.
2. **Работа с PostgreSQL: `pgx/v5` + `sqlc`**
    - *Обоснование:* Отказ от тяжеловесных ORM в пользу кодогенерации `sqlc`. Это дает строгую type-safe проверку
      SQL-запросов на этапе компиляции, высокую производительность (благодаря `pgx`).
3. **Миграции БД: `golang-migrate/migrate`**
    - *Обоснование:* Индустриальный стандарт для Go-приложений, хорошая интеграция с CI/CD, поддержка накатывания из
      кода (go:embed) и через CLI. Используется в при разработке в YADRO.
4. **Тестирование: `testify` + `testcontainers-go`**
    - *Обоснование:* `testify` для модульного тестирования, `testcontainers` для интеграционного слоя репозитория.
      Это позволит поднимать реальный инстанс PostgreSQL в Docker прямо из тестов, исключая моки на слое БД.
5. **Метрики и сбор логов: `VictoriaMetrics` + `VictoriaLogs` + `Grafana`**
    - *Обоснование:* Выбор такой связки обоснован прежде всего экстремальной производительностью, снижением затрат на
      инфраструктуру и простотой эксплуатации по сравнению с классическим стеком Prometheus + Loki + Grafana.

## Последствия

* **Позитивные:** Строгая типизация на всех слоях, высокая производительность, отсутствие оверхеда фреймворков,
  готовность к production.
* **Негативные:** `sqlc` требует написания сырых DDL и SQL-запросов вручную перед генерацией кода, что может
  незначительно замедлить старт разработки схемы БД.
